# 0004 · 레이트리밋을 인스턴스 메모리에 둔다

## 결정

`/api/chat`(10회/분)과 `/api/contact`(3회/분)의 레이트리밋을 모듈 최상위 `Map`에 둔다.
외부 저장소를 쓰지 않는다.

## 맥락

서버리스에서 이 결정의 결과를 **알면서 수용했다**:

- 인스턴스마다 카운터가 따로 있다 → 실제 허용량은 `한도 × 인스턴스 수`다.
- 재배포하면 초기화된다.

1인 포트폴리오에서 이 리밋의 목적은 정밀한 쿼터 집행이 아니라 **명백한 남용과 사고성 반복 호출을
싸게 막는 것**이다. 그 목적에는 인스턴스 로컬로 충분하다.

## 포기한 대안

- **Redis/Upstash** — 외부 의존이 하나 늘고, 그 순간 "자격증명 0으로 CI가 전부 통과한다"는
  이 저장소의 self-contained 계약(→ [0005](0005-env-gated-degradation.md))이 깨진다.
- **Vercel Edge Config / KV** — 같은 이유 + 플랫폼 락인.

## 강제하는 가드

`verify:runtime`의 V8. 이 하네스는 `/api/contact`를 4케이스 호출하는데,
**케이스마다 `x-forwarded-for`를 바꾼다** — 안 바꾸면 4번째가 503이 아니라 429가 되어 가짜 실패가 난다.
그 코드가 곧 이 결정의 실행 가능한 데모다.

## 재검토 트리거

실제 남용이 관측되면(로그에 동일 출처 대량 호출) 그때 외부 저장소를 도입한다.
그 시점에는 CI 계약을 지키기 위해 "미설정이면 인메모리로 축소"하는 형태여야 한다.
