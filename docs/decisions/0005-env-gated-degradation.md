# 0005 · 자격증명이 없으면 죽는 대신 축소한다

## 결정

외부 의존(Groq·Gmail SMTP·GA4·검색 콘솔)은 환경변수가 없으면 **해당 기능만 비활성화**되고
나머지는 전부 정상 동작한다. 기동 시 필수 환경변수 검사로 죽이지 않는다.

## 맥락

**이 저장소의 Port/Adapter가 바로 이것이다.** `isChatConfigured()`가 Port이고,
자격증명의 유무가 어댑터 스위치다. 그래서 시크릿 하나 없이도 전 경로가 도는 CI가 성립한다.

관측 가능한 계약(실측):

| 조건 | 관측 |
|---|---|
| `GROQ_API_KEY` 없음 | `GET /api/chat` → `{"available":false}` · `POST` → 503 |
| `GROQ_API_KEY`가 더미 값 | 네트워크 호출 없이 입력 검증 분기(400)까지 열린다 |
| `GMAIL_USER`/`PASS` 없음 | `POST /api/contact` → 503 `{fallback:true}`. 검증(400)·레이트리밋(429)은 정상 |

`/api/contact`는 검증 → 레이트리밋 → 자격증명 순서라 자격증명 없이도 로직 전체가 관측된다.
`/api/chat`은 반대로 자격증명 체크가 body 파싱보다 앞이라 더미 키가 있어야 검증 분기가 열린다 —
`verify:runtime`이 이 슬라이스를 두 번(키 없음 / 더미 키) 도는 이유다.

## 포기한 대안

- **기동 시 필수 환경변수 검증 후 종료** — 흔한 패턴이지만 여기서는 CI가 시크릿을 요구하게 되고,
  처음 클론한 사람이 아무것도 못 돌린다.
- **모킹 서버(Groq 스텁)** — `lib/chat/groq.ts`가 SDK 생성자에 `baseURL`을 노출하지 않아
  소스 변경 + 신규 배관이 필요하고, 얻는 것은 "SDK가 스트림을 잘 파싱하는가"라는 남의 코드 검증이다.

## 강제하는 가드

`verify:runtime`의 V8(축소 계약)·V9(검증 계약). `pnpm preflight`가 무엇이 축소됐는지 출력하며,
**축소는 exit 0이고 exit 1은 진짜로 막힌 것에만 쓴다** — 이 구분이 없으면 에이전트가
축소를 고장으로 오인해 불필요한 수정을 시도한다.

## 재검토 트리거

**새 외부 의존을 붙일 때 반드시 이 규칙을 따른다.** 상태를 가진 의존(DB·큐)이 들어와
"없으면 축소"가 성립하지 않는 순간이 재검토 시점이고, 그때는 컨테이너화를 함께 검토한다.
