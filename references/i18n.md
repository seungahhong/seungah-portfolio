# i18n

## 원칙

**표시 문구는 100% `src/lib/i18n/{ko,en}.json`.** 데이터 파일과 컴포넌트에는 문구를 두지 않는다.
`src/helpers/datas/**`가 담는 것은 id·날짜·URL·이미지 경로·기술명처럼 언어와 무관한 값뿐이다.

## API

```ts
t(locale, 'career.companies.wadiz.summary')          // 문자열
t(locale, 'career.more', { count: 3 })               // {count} 치환
tList(locale, 'about.descriptions')                  // 문자열 배열
hasTranslation(locale, '...linkTitle')               // 선택 항목 분기
useT()                                               // 클라이언트: { t, tList, has, locale }
```

- 키는 **중첩 JSON을 향한 점 표기 경로**다. 평면 키가 아니다.
- **못 찾으면 키 문자열을 그대로 반환한다.** 예외가 없으므로 오타는 화면에서만 드러난다.
- 영어에 키가 없으면 한국어로 폴백한다 — 화면이 비지는 않지만 언어가 섞이므로 파리티를 지켜야 한다.

## 파리티 규칙

ko.json과 en.json은 **키 구조와 배열 길이까지 완전히 같아야 한다**. 배열(`points`, `imageAlts`,
`descriptions`, `items`)은 인덱스로 짝지어지므로 길이가 달라지면 조용히 어긋난다.

검증 방법은 `verification.md`의 파리티 스크립트 참고.

## 로케일 결정

URL이 유일한 출처다(`/` = ko, `/en` = en). 쿠키·localStorage·마운트 후 보정 없음.
루트 레이아웃이 `ClientProviders`에 로케일을 내려주므로 서버 첫 렌더부터 클라이언트까지 같은 언어다.

```ts
localizedPath('en', '/career/wadiz')  // '/en/career/wadiz'
neutralPath('/en/career/wadiz')       // '/career/wadiz'   — 언어 전환 시 짝 찾기
```

내부 링크는 문자열을 조립하지 말고 위 헬퍼를 쓴다. 언어 토글은 상태 토글이 아니라
같은 문서의 다른 언어 URL로 이동하는 **링크**다(크롤러가 관계를 따라갈 수 있어야 한다).

## 기술블로그 링크

블로그는 한/영 1:1로 운영된다(`/ko/posts/{slug}/`, `/en/posts/{slug}/`, slug 동일).
따라서 데이터에는 **절대 URL이 아니라 `blogSlug`를 저장**하고 `blogPostUrl(locale, slug)`로 조립한다.
영어 페이지에서 한국어 글로 보내지 않기 위해서다. 블로그가 아닌 외부 링크만 `url`에 절대 주소로 둔다.

## 클라이언트 컴포넌트 주의

컨텍스트만 쓰면 SSR 시점에는 기본 로케일로 그려진다. 서버에서 로케일을 아는 컴포넌트
(`ContactSection`, `ChatTab`, `ChatInput`, `SuggestionChips`)는 `locale`을 **prop으로 받아**
`t(locale, key)`를 직접 호출한다. 이 패턴을 깨면 한 화면에 두 언어가 섞인다.
